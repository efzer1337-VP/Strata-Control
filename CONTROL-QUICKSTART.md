# Strata Control

## Окно приложения Desktop 4.1

`STRATA-CONTROL.bat` открывает обычное окно приложения. Светлая оливковая тема и боковая навигация помогают переходить между настройками, чатом и показателями ресурсов.

При выборе Strata используются её прежние параметры: контекст, KV-кэш, резидентные эксперты, speculative decoding и vision. Параметры другого движка доступны отдельно после его выбора. Сохранённые профили сохраняют свои значения.

Выберите движок и профиль, поменяйте параметры, сохраните изменения и нажмите «Запустить». На вкладке **Чат и API** можно переписываться с моделью, прикреплять изображения и видеть RAM, VRAM, загрузку GPU, число токенов и скорость ответа. Браузер для этого не нужен.

После обновления закройте старое окно Control и откройте BAT заново. Заголовок новой версии — «Strata Control · Desktop 4.1». Закрытие Control оставляет сервер модели работать.

## Движки и именованные профили

В «Рабочей конфигурации» выберите **движок**, затем модель/профиль.

- **Strata** использует прежние конфигурации и свои параметры; старые файлы не изменяются при открытии окна.
- **llama.cpp** устанавливается кнопкой **Движки / установить…**. Есть CUDA для NVIDIA и CPU. Скачиваются только официальный сервер и его библиотеки; веса моделей не скачиваются. CUDA-архив подбирается по версии драйвера, если её удалось определить.
- **PolyStrata** находится в `Strata-data/polystrata` и появляется в списке автоматически после локальной сборки. Для Ornith у него отдельная вкладка с контекстом, кэшем бесед, запасами памяти, окном MTP и vision. Параметры llama.cpp к PolyStrata не применяются.
- Уже подключённый Turbo и официальный llama.cpp сохраняются как разные варианты движка. Профиль привязан к выбранному варианту.
- Другой нативный сервер можно установить из локального ZIP или подключить существующий EXE. Для `llama-server.exe` включается адаптер llama.cpp. Для NInfer и других пользовательских EXE нужен шаблон аргументов самого движка и совместимый GPU; регистрация EXE не означает совместимость всех моделей или оборудования.

После выбора llama.cpp нажмите **Добавить модель**, выберите локальный GGUF, настройте контекст, GPU layers, потоки CPU, KV и необязательный mmproj на вкладке **Другой движок**. Поля Strata для него выключаются. Формат модели, качество контекста и vision определяет выбранный движок.

Для MoE-моделей доступны отдельные поля: число слоёв экспертов в RAM, параллельные слоты, кэш RAM, физический пакет, лимит размышления и автоматический подбор VRAM. Стартовые значения для Ornith на этом ПК и порядок замеров: [ORNITH-SETUP.md](ORNITH-SETUP.md). Установленные здесь веса лежат в `Strata/Strata-data`; сохранённый путь установщика указывает на эту папку.

Для новой Ornith Uncensored доступны профили llama.cpp Q4 и PolyStrata Q3. Профили llama.cpp включают `--load-mode none`; на этом ПК после загрузки Q4 оставалось 13,6–14,6 ГиБ RAM. Профиль PolyStrata быстрее в коротком локальном замере, но оставляет около 3,5 ГиБ RAM: выбирайте его, когда закрыты другие тяжёлые приложения. Он использует собственный кэш экспертов и отдельный vision-энкодер на CPU. Подробности: [ORNITH-SETUP.md](ORNITH-SETUP.md).

Для пользовательского EXE каждый токен аргументов указывается на отдельной строке. Шаблоны: `{model}`, `{context}`, `{port}`, `{host}`; `{host}` подставляется как `127.0.0.1`. Сверяйте имена флагов с документацией подключённого сервера. GPU/KV-поля и режим размышления применяются только к адаптеру llama.cpp. Команда выполняется без shell.

**Сохранить профиль как…** создаёт отдельную копию всех параметров, привязанную к модели и движку. Например: «Coder · 128K · работа» и «Coder · 262K · максимум». Выбор имени в верхнем списке загружает его настройки; запущенный сервер не переключается сам. Для применения используйте остановку/запуск или перезапуск выбранного профиля. Если предыдущий сервер занимает тот же порт, сначала остановите его.

**Импорт / экспорт профиля** переносит настройки через JSON. Модель и движок не включаются в этот файл. На другом ПК подключите нужный движок и проверьте локальные пути. Не передавайте профили с приватными переменными окружения или ключами посторонним.

Профили и реестр находятся в `.strata-control/`; выбранный профиль запоминается между открытиями. Эти данные исключены из Git и сборки для передачи. Для всех поддерживаемых процессов работает управление запуском, остановкой и RAM-сторожом. У llama.cpp VRAM-резерв — цель fit; у пользовательских движков он не применяется автоматически.

Регулярная проверка процессов, HTTP API и памяти выполняется в фоне. Остановка сервера и установка движка также идут в фоне, чтобы окно оставалось отзывчивым. Закрытие Control оставляет запущенные серверы работать.

Дважды нажмите ярлык **Strata Control** или `STRATA-CONTROL.bat`. Менять BAT-файлы не нужно.

## Запуск

1. Выберите модель в верхнем списке.
2. Настройте запас RAM и VRAM на вкладке «Ресурсы ПК» или «PolyStrata · Ornith».
3. Нажмите **Запустить** и перейдите на вкладку **Чат и API**.

**Остановить** завершает сервер выбранного профиля. **Перезапустить** применяет новые параметры. Закрытие окна Control оставляет сервер работать.

Выбранная модель запоминается между запусками. Настройки каждой модели сохраняются отдельно.

## Добавление скачанной модели

1. Остановите работающий сервер, чтобы освободить память для подготовки.
2. Нажмите **+ Добавить модель**.
3. Выберите первый GGUF (`00001-of-….gguf`). Остальные части должны лежать в той же папке.
4. Подтвердите подготовку и дождитесь сообщения «Готово».
5. Проверьте параметры и нажмите **Запустить**.

Эта процедура подготавливает модели для **движка Strata**: Qwen3.8 GSQ-RCO, Coder IQ1_M, Swift 1.5 и Unsloth UD-IQ4_XS / UD-Q4_K_XL. Ornith добавлена отдельными готовыми профилями для llama.cpp и PolyStrata: её GGUF не нужно подготавливать через Strata.

Добавление модели не скачивает файлы. Можно выбрать любую часть GGUF — приложение найдёт первую; все части проверяются перед подготовкой. Подготовленные данные помещаются в `packs/control-…` внутри папки данных, выбранной в настройках установщика. При обычном Resident-режиме создаётся дополнительный файл экспертов; для него могут потребоваться десятки ГБ места. Unsloth читает экспертов прямо из GGUF. Старый профиль и его подготовленные данные сохраняются.

Новая модель получает отдельный начальный профиль: контекст 32K, int8 KV, запас RAM до 8 ГиБ (четверть памяти, если RAM меньше 32 ГиБ), запас VRAM 2 ГиБ, expert cache auto. Это стартовые настройки запускатора, а не измеренный оптимум производительности. Они не изменяют старую модель. Совместимый стандартный mmproj рядом с моделью подставляется в поле; vision остаётся выключен.

Для vision включите соответствующий переключатель на вкладке «Модель и vision», выберите совместимый `mmproj` кнопкой **Обзор…** и сохраните настройки.

## Выбор модели и параметров

- Вкладка **Какие модели выбрать** показывает семейства и размеры из текущего `setup.py`, приблизительный размер GGUF и ориентир RAM. Это не прогноз скорости и не гарантия запуска.
- В верхней карточке видны семейство, квантовка, режим экспертов и приблизительный объём экспертов.
- Кнопка **Настройки с запасом** устанавливает 32K контекст, int8 KV и запасы RAM/VRAM. Применяется только по нажатию и после сохранения.
- **MTP** можно отключить. Spec больше нуля допускает черновики по совпадениям с контекстом без MTP; **Spec = 0** выключает спекуляцию. Путь к runtime запоминается при выключении MTP.
- Пресеты контекста доходят до **524288**. Выше обученных 262144 автоматически включается YaRN с соответствующим коэффициентом. Эффективность и качество такого расширения на этом ПК не измерялись.
- **Lazy** открывает API без загрузки модели и vision. Они загрузятся при первом запросе. Остановка сервера по-прежнему завершает весь выбранный процесс.
- Для Unsloth при включённом RAM-резерве бюджет экспертов дополнительно ограничивается рекомендацией setup: оставить 24 ГиБ для системы, движка и файлового кэша, с учётом RAM для потокового KV. Заданный резерв RAM всё равно контролируется отдельным сторожем.

Объяснение устройства Strata и различий моделей: [CONTROL-RESEARCH.md](CONTROL-RESEARCH.md).

## Если ярлык перестал открывать приложение

Запускатор ищет Python в текущей папке и во вложенной полной установке. Если установленная папка не найдена, предлагает выбрать её через окно и запоминает выбор. Если Python повреждён, предлагает открыть восстановление Strata. Для ещё не установленной копии сначала используйте `INSTALL.bat` из полного архива.

При сбое запуска окна причина сохраняется в `.strata-control-startup.log`. При раннем завершении сервера приложение показывает конец журнала; полный журнал доступен кнопкой **Журнал**.

## Оформление

Настольное окно использует тёмную тему с оливковым акцентом и шрифт Windows Segoe UI. Чат, состояние сервера и показатели ресурсов находятся в одном окне.
