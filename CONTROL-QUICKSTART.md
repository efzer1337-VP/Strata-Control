# Strata Control

## Установка из репозитория

Распакуйте репозиторий в выбранную папку и запустите `INSTALL.bat` (также работает `INSTAL.bat`). Выберите Strata, PolyStrata или оба движка. В вопросе о модели Enter означает «пропустить»: Python, зависимости и движок устанавливаются отдельно от весов. Control открывается и без профиля модели. Модель установщик не запускает.

Окружение `.venv`, движки, модели и подготовленные данные находятся внутри этой папки; данные моделей идут в `Strata-data/`. Если подходящего Python нет, он устанавливается в `.python/` внутри репозитория. Установщик не меняет PATH и не переносит модели из других установок Strata.

Для PolyStrata предлагаются стандартная Ornith и [Ornith 1.5 Uncensored](https://huggingface.co/dealignai/Ornith-1.5-35B-A3B-UNCENSORED-GGUF): Q4_K_M (21,7 ГБ) или Q3_K_M (17,2 ГБ). Скачивание проверяется по размеру и SHA-256. Зрение запрашивается отдельно штатным setup. Оценки памяти в меню Uncensored являются оценками установщика, а не замерами скорости или гарантией запуска на конкретном GPU.

Без вопросов и без весов: `INSTALL.bat --yes --no-model`; для PolyStrata добавьте `--engine polystrata`. Для скачивания Uncensored: `INSTALL.bat --engine polystrata --model-choice uncensored`. Повторный запуск позволяет добавить модель позже. Штатный `START-HERE.bat` сохраняет свой прежний сценарий установки.

## Панель управления 4.3

`STRATA-CONTROL.bat` открывает локальную панель в отдельном окне установленного Edge или в браузере. Панель слушает только `127.0.0.1`, проверяет Host, Origin и токен запросов. Светлая оливковая тема сохранена.

При выборе Strata используются её прежние параметры: контекст, KV-кэш, резидентные эксперты, speculative decoding и vision. Параметры другого движка доступны отдельно после его выбора. Сохранённые профили сохраняют свои значения.

Выберите **Strata** или **PolyStrata** постоянными кнопками вверху, затем модель/профиль. Последний профиль каждого движка запоминается отдельно. llama.cpp и пользовательские EXE доступны в списке под этими кнопками. Если профилей нет, добавьте модель или импортируйте профиль.

Переключение и сохранение не перезапускают сервер. При несохранённых правках доступны «Сохранить и перейти», «Отбросить» и «Отмена»; Escape отменяет переход. Если другой профиль работает, Control показывает его имя и порт и предлагает сначала остановить его. Запуск второго управляемого сервера блокируется.

В Control нет встроенной переписки или Harness/Coding Agent. «Открыть страницу сервера» и «Открыть монитор» открывают отдельные страницы.

После обновления закройте старое окно Control и откройте BAT заново. Заголовок новой версии: «Strata Control · 4.3». Закрытие Control оставляет сервер модели работать.

## Исследованные настройки и пресеты

Кнопка **Очистить RAM + VRAM** справа над «Ресурсами компьютера» доступна во время работы модели. В Windows она сбрасывает рабочий набор системного файлового кэша через `SetSystemFileCacheSize(-1, -1, 0)`; при необходимости запрашивает права администратора только для отдельного помощника. Программы и генерация продолжают работать. Повторное чтение файлов может замедлиться. Это не очистка всей занятой RAM или standby-списка. Общесистемной очистки VRAM без участия владеющих ею приложений нет; результат явно сообщает, что VRAM не очищалась. В «Операциях Control» показаны доступная RAM до и после операции и ошибки, включая отмену запроса прав. Изменение показаний относится ко всему ПК и не является измерением объёма очищенного кэша. На Linux эта операция не поддерживается.

В разделе **Стартовый пресет** доступны «С запасом памяти» (32K), «Несколько клиентов» (32K и ограниченный RAM-кэш бесед) и «Длинный контекст» (128K). Раскройте **Какие настройки изменятся**, затем нажмите **Применить к черновику**. Файл профиля и работающий сервер от этого не изменяются. Сохраните профиль отдельно; для применения к запущенной модели нужен явный перезапуск.

У новых полей можно оставить пустое значение, чтобы наследовать настройку движка/подготовленного JSON. Доступны CPU/prefill, кэши, sampling, reasoning, выгрузка при простое и таймаут; набор соответствует выбранному движку. Для PolyStrata добавлены её буферы и черновики. Нулевой бюджет размышления означает отсутствие лимита; отключение задаётся уровнем `none`.

Пресеты не меняют файлы модели, MTP, vision, порт, окружение и параметры генерации. Они не являются измеренным оптимумом. Полный список параметров, диапазоны, первичные источники и ограничения: [исследование настроек Control](docs/CONTROL-PARAMETERS.md).

## Движки и именованные профили

Вверху выберите **движок**, затем модель/профиль. Под выбором показаны ограничения адаптера. Пути файлов, контекст, MTP, vision и известные требования backend проверяются до запуска.

- **Strata** использует прежние конфигурации и свои параметры; старые файлы не изменяются при открытии окна.
- **llama.cpp** устанавливается кнопкой **Управление движками**. Есть CUDA для NVIDIA и CPU. Скачиваются только официальный сервер и его библиотеки; веса моделей не скачиваются. CUDA-архив подбирается по версии драйвера, если её удалось определить.
- **PolyStrata** находится в `Strata-data/polystrata` и всегда виден вверху, в том числе до установки. Его контекст, KV, кэш бесед, запасы памяти, окно MTP и vision показаны отдельными полями. Для другой модели укажите подготовленный JSON этой модели. Нельзя заменить GGUF и оставить чужие токенизатор и профиль экспертов. Параметры llama.cpp к PolyStrata не применяются.

Другую квантовку PolyStrata можно использовать с той же подготовленной конфигурацией, если заголовки GGUF подтверждают одинаковые архитектуру, токенизатор и формы тензоров. Control сверяет эти данные без чтения весов и запоминает результат до изменения файла. Это проверка контракта ресурсов, а не подтверждение качества или GPU-совместимости конкретной квантовки.
- Уже подключённый Turbo и официальный llama.cpp сохраняются как разные варианты движка. Профиль привязан к выбранному варианту.
- Другой нативный сервер можно установить из локального ZIP или подключить существующий EXE. Для `llama-server.exe` включается адаптер llama.cpp. Для NInfer и других пользовательских EXE нужен шаблон аргументов самого движка и совместимый GPU; регистрация EXE не означает совместимость всех моделей или оборудования.

После выбора llama.cpp нажмите **Добавить модель**, выберите локальный GGUF, настройте контекст, GPU layers, потоки CPU, KV и необязательный mmproj в группах настроек. Поля Strata для него не показываются. Для пользовательского EXE доступны общие поля и шаблон аргументов, без обещания поддержки llama.cpp-параметров. Формат модели, качество контекста и vision определяет выбранный движок.

Для MoE-моделей доступны отдельные поля: число слоёв экспертов в RAM, параллельные слоты, кэш RAM, физический пакет, лимит размышления и автоматический подбор VRAM. Стартовые значения для Ornith на этом ПК и порядок замеров: [ORNITH-SETUP.md](ORNITH-SETUP.md). Установленные здесь веса лежат в `Strata/Strata-data`; сохранённый путь установщика указывает на эту папку.

Для новой Ornith Uncensored доступны профили llama.cpp Q4 и PolyStrata Q3. Профили llama.cpp включают `--load-mode none`; на этом ПК после загрузки Q4 оставалось 13,6–14,6 ГиБ RAM. Профиль PolyStrata быстрее в коротком локальном замере, но оставляет около 3,5 ГиБ RAM: выбирайте его, когда закрыты другие тяжёлые приложения. Он использует собственный кэш экспертов и отдельный vision-энкодер на CPU. Подробности: [ORNITH-SETUP.md](ORNITH-SETUP.md).

Для пользовательского EXE каждый токен аргументов указывается на отдельной строке. Шаблоны: `{model}`, `{context}`, `{port}`, `{host}`; `{host}` подставляется как `127.0.0.1`. Сверяйте имена флагов с документацией подключённого сервера. GPU/KV-поля и режим размышления применяются только к адаптеру llama.cpp. Команда выполняется без shell.

**Создать копию** создаёт отдельную копию всех параметров, привязанную к модели и движку. Например: «Coder · 128K · работа» и «Coder · 262K · максимум». Выбор имени в верхнем списке загружает его настройки; запущенный сервер не переключается сам. Для применения используйте остановку/запуск или перезапуск выбранного профиля. Если предыдущий сервер занимает тот же порт, сначала остановите его.

**Импорт / экспорт профиля** переносит настройки через JSON. Модель и движок не включаются в этот файл. На другом ПК подключите нужный движок и проверьте локальные пути. Не передавайте профили с приватными переменными окружения или ключами посторонним.

Профили и реестр находятся в `.strata-control/`; выбранный профиль запоминается между открытиями. Эти данные исключены из Git и сборки для передачи. Для всех поддерживаемых процессов работает управление запуском, остановкой и RAM-сторожом. У llama.cpp VRAM-резерв — цель fit; у пользовательских движков он не применяется автоматически.

Регулярная проверка процессов, HTTP API и памяти выполняется в фоне. Остановка сервера и установка движка также идут в фоне, чтобы окно оставалось отзывчивым. Закрытие Control оставляет запущенные серверы работать.

Дважды нажмите ярлык **Strata Control** или `STRATA-CONTROL.bat`. Менять BAT-файлы не нужно.

## Запуск

1. Выберите движок и модель/профиль вверху.
2. Проверьте совместимость, параметры памяти и контекста.
3. Нажмите **Запустить**. Готовность, адрес API и ошибки видны в панели сервера; операции и ресурсы находятся рядом. Кнопка **Перезапустить** применяет параметры только по вашему действию.

**Остановить** завершает сервер выбранного профиля. **Перезапустить** применяет новые параметры. Закрытие окна Control оставляет сервер работать.

Выбранная модель запоминается между запусками. Настройки каждой модели сохраняются отдельно.

## Добавление скачанной модели

1. Остановите работающий сервер, чтобы освободить память для подготовки.
2. Нажмите **+ Добавить модель**.
3. Выберите первый GGUF (`00001-of-….gguf`). Остальные части должны лежать в той же папке.
4. Подтвердите подготовку и дождитесь сообщения «Готово».
5. Проверьте параметры и нажмите **Запустить**.

Эта процедура подготавливает модели для **движка Strata**: Qwen3.8 GSQ-RCO, Coder IQ1_M, Swift 1.5 и Unsloth UD-IQ4_XS / UD-Q4_K_XL. Ornith добавлена отдельными готовыми профилями для llama.cpp и PolyStrata: её GGUF не нужно подготавливать через Strata.

Добавление модели не скачивает файлы. Можно выбрать любую часть GGUF — приложение найдёт первую; все части проверяются перед подготовкой. Подготовленные данные помещаются в `packs/control-…` внутри папки данных, выбранной в настройках установщика. При обычном Resident-режиме создаётся дополнительный файл экспертов; для него могут потребоваться десятки ГБ места. Unsloth читает экспертов прямо из GGUF. Старый профиль и его подготовленные данные сохраняются.

Новая модель получает отдельный начальный профиль: контекст 32K, int8 KV, запас RAM до 8 ГиБ (четверть памяти, если RAM меньше 32 ГиБ), запас VRAM 2 ГиБ, expert cache auto. Это стартовые настройки запускатора, а не измеренный оптимум производительности. Они не изменяют старую модель. Совместимый стандартный mmproj рядом с моделью подставляется в поле; vision остаётся выключен.

Для vision включите соответствующий переключатель в группе «Изображения», выберите совместимый `mmproj` кнопкой **Обзор…** и сохраните настройки.

## Выбор модели и параметров

- Каталог **Какие модели поддерживает Strata** в окне **Управление движками** показывает семейства и размеры из текущего `setup.py`, приблизительный размер GGUF и ориентир RAM. Это не прогноз скорости и не гарантия запуска.
- В верхней карточке видны семейство, квантовка, режим экспертов и приблизительный объём экспертов.
- Кнопка **Настройки с запасом** устанавливает 32K контекст, int8 KV и запасы RAM/VRAM. Применяется только по нажатию и после сохранения.
- **MTP** можно отключить. Spec больше нуля допускает черновики по совпадениям с контекстом без MTP; **Spec = 0** выключает спекуляцию. Путь к runtime запоминается при выключении MTP.
- Пресеты контекста доходят до **524288**. Выше обученных 262144 автоматически включается YaRN с соответствующим коэффициентом. Эффективность и качество такого расширения на этом ПК не измерялись.
- **Lazy** открывает API без загрузки модели и vision. Они загрузятся при первом запросе. Остановка сервера по-прежнему завершает весь выбранный процесс.
- Для Unsloth при включённом RAM-резерве бюджет экспертов дополнительно ограничивается рекомендацией setup: оставить 24 ГиБ для системы, движка и файлового кэша, с учётом RAM для потокового KV. Заданный резерв RAM всё равно контролируется отдельным сторожем.

Объяснение устройства Strata и различий моделей: [CONTROL-RESEARCH.md](CONTROL-RESEARCH.md).

## Если ярлык перестал открывать приложение

Запускатор ищет Python в текущей папке и во вложенной полной установке. Если установленная папка не найдена, предлагает выбрать её через окно и запоминает выбор. Если Python повреждён, предлагает открыть восстановление Strata. Для ещё не установленной копии сначала используйте `INSTALL.bat` из полного архива.

При сбое запуска панели причина сохраняется в `.strata-control/web-control.log`; прямой запуск через старый Python-файл также может записать `.strata-control-startup.log`. При раннем завершении сервера панель показывает код завершения, причина доступна на вкладке **Журнал**.

## Оформление

Панель использует светлую тему с оливковым акцентом и системный шрифт Segoe UI. Настройки сгруппированы по назначению; доступны поиск, избранное, многострочные аргументы и пресеты контекста до 524288 токенов. При узком окне панели располагаются друг под другом. У элементов есть клавиатурный фокус; уменьшение анимации учитывается.

Ресурсы показывают текущее использование всего ПК, RAM/VRAM в ГиБ и загрузку CPU/GPU в процентах. Без телеметрии выводится «Недоступно». Для Strata и PolyStrata Control читает существующий `/metrics`: контекст, слоты кэша экспертов, текущую скорость и очередь, отдельно счётчики токенов за сессию. При остановленном сервере старые показатели не выдаются за текущие. RAM-сторож и операции показаны отдельно. Журнал общий для запусков через Control и содержит разделители с именами файлов профилей.
